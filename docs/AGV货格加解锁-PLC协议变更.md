# PLC 协议变更：货格加解锁（寄存器表 V8 → V9）

## 1. 变更概览

| 项 | 内容 |
|---|---|
| 读区新增 | 341~356：站口 1~16 加锁状态（0=未锁 / 1=已锁） |
| 命令区扩展 | 401~416 新增命令码 3=加锁 / 4=解锁（原 0/1/2 不变） |
| 触发/回显 | 机制不变：400 新值触发、回显匹配为唯一成功标准 |
| 版本 | 寄存器表 V9 草案已出：docs/BufferC-PLC寄存器表_V9.xlsx（评审通过后替换 V8） |

## 2. 读区新增：站口加锁状态回读（341~356）

| 地址 | 内容 | 说明 |
|---|---|---|
| 341~356 | 站口 1~16 加锁状态 | 0=未锁 / 1=已锁；物理槽位排列（与 307~322 同口径）；PLC 上电初始化全 0；加锁期间 PLC 不得自行清零（BufferC 以 341 为权威） |

- 占用原空闲区 341~399 的前 16 字；属可自由 FC03 读区域（非 400~672 禁读区）。
- BufferC 每轮轮询独立短读 341~356（与 306~340 主轮询分开、独立容错：V8 PLC 读失败不影响主轮询），锁状态实时刷新。

## 3. 命令区扩展：新增命令码 3/4（401~416）

| 地址 | 现有 | 变更 |
|---|---|---|
| 401~416（各站操作命令） | 0=无 / 1=写入货物ID / 2=删除货物ID | 新增 3=加锁 / 4=解锁 |

- 触发机制不变：先清零 401~672 → BufferC 写命令码到 401+(物理槽-1) → 写 400 新编号触发 → PLC 执行。
- 回显机制不变：PLC 回写 306=400 值、307+(物理槽-1)=命令码；回显匹配是 BufferC 判定命令成功的唯一标准。

## 4. PLC 侧处理要求（与供应商确认事项）

1. 收到命令 3（加锁）→ 置 341+(物理槽-1) = 1；收到命令 4（解锁）→ 清 341+(物理槽-1) = 0。
2. 命令幂等：重复置同值无副作用。
3. 341~356 上电初始化全 0；除命令 4 与初始化外 PLC 不得自行清 0（BufferC 超时解锁会主动发命令 4）。
4. 回显规则同现有命令 1/2。
5. （建议）加锁期间 PLC 侧对该格机械/流程的联锁动作（如禁取放、指示灯）由 PLC 侧定义，回填寄存器表说明列。

## 5. BufferC 转发流程（内部口径）

AGV 加锁请求 → 消息去重（GUID）→ 站口已锁 → 直接返回成功；未锁 → 命令通道下发命令码 3
（复用清零→写码→400 触发→回显匹配→重试）
  → 回显成功 → 回读 341~356 确认置位 → 返回成功
  → 回显超时重试后仍失败 → 返回失败（message：PLC 转发失败；本侧不记锁/保持原状态）
（解锁同理：站口未锁 → 直接返回成功；已锁 → 下发命令码 4）

失败路径：转发失败不记锁（解锁失败保持锁），记 WARN/审计；命令通道复用现有 5s 超时 + 1 次重试，但锁命令不置 9001（非 MCS 悬空命令）。

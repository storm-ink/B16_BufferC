# AGV 货格加解锁接口协议

AGV 执行放货任务前，对目标货格加锁；任务完成后解锁。BufferC 收到信号后转发 PLC（见 PLC 协议变更文档）。
货格 = 站口（1 站 1 格，每机台 16 站）。

## 1. 端点

POST http://<BufferC-IP>:<webPort>/api/agv/cellLock
Content-Type: application/json

AGV（或 AGVC 代发）直接调用 BufferC。恒返回 HTTP 200，业务结果看 code 字段。

## 2. 请求字段（核心 4 个）

| 字段 | 必填 | 说明 |
|---|---|---|
| time | 是 | 交互时间，yyyy-MM-dd HH:mm:ss（也容忍 ISO / yyyyMMddHHmmss） |
| guid | 是 | 交互 GUID：随机数，1~64 字符；每条消息唯一（标识该条消息，用于消息去重） |
| cmsIndex | 是 | 任务存放目标位置 = 机台号×10000 + 站口（如 10001 = 1 号机台 1 号站口）；字符串 |
| action | 是 | 加解锁标识：lock = 加锁 / unlock = 解锁 |

请求示例：
{"time":"2026-10-10 14:23:05","guid":"AGVTASK-20261010-000001","cmsIndex":"10001","action":"lock"}

## 3. 响应

| 字段 | 说明 |
|---|---|
| code | "0" = 成功（含幂等重复请求）；"1" = 失败 |
| message | 结果描述（中文，供人工排障） |

响应示例（成功）：{"code":"0","message":"加锁成功"}
响应示例（幂等重复）：{"code":"0","message":"重复消息（幂等）"}
响应示例（失败）：{"code":"1","message":"PLC 转发失败"}

## 4. 失败情形（code=1，原因见 message）

| 失败情形 | message 示例 |
|---|---|
| 参数错误（缺字段 / cmsIndex 或 action 非法 / JSON 格式错误） | "参数错误：cmsIndex 非法" |
| PLC 转发失败 / PLC 离线 | "PLC 转发失败" / "PLC 离线" |

## 5. 交互规则

1. 消息去重：GUID 为随机数、每条消息唯一；同一 GUID 再次到达 = 该消息的重发 → 此前已成功/幂等则直接返回成功、不重复下发 PLC；此前失败则允许真正重发（失败消息不会被当成成功重放）。
2. 加锁：站口未锁 → 加锁成功；已锁 → 也返回成功（幂等，不重复下发 PLC）。
3. 解锁：站口已锁 → 解锁成功；未锁 → 也返回成功（幂等）。
4. 运维提前释放：直接发送解锁消息即可（不校验发送方；本版无锁状态界面，可调接口或查 `GET /api/agv/locks`，审计留痕）。
5. 超时兜底：加锁成功后若超时未解锁（默认 30 分钟，可配置），BufferC 自动补发解锁，记 WARN 日志 + 审计（不发 9002 / S5F1 告警），防 AGV 异常死锁。
6. 无鉴权（厂区内网，与现有 Web/HSMS 同信任域）。
7. AGV 侧 HTTP 超时应 ≥ 15s（最坏情形含 PLC 回显重试链）。

## 6. 配套查询（非 AGV 必需，供 UI/联调）

- GET  /api/agv/locks  查询全部站口锁状态与最近交互信息（供 UI/联调）

## 7. BufferC 实现口径（2026-10-23）

1. **341~356 为权威**：每次请求先直读目标站位的 341 判断幂等，命令成功后再次回读确认；转发失败或回读不一致一律不记锁。
2. **GUID 去重**：同 GUID + 同 cmsIndex + 同 action 且此前结果为成功/幂等 → 返回 code=0「重复消息（幂等）」、不重复下发；此前结果为失败的 GUID 允许重发（失败消息不能被当成成功重放）。
3. **超时计时**用 BufferC 收报时间（报文里的 time 仅留痕）；默认 30 分钟（`cellLockTimeoutMinutes`，0=关闭）；已锁站口用新 GUID 再次加锁会刷新计时与持有者。
4. **接口恒启用**（无开关）；PLC 未实现 V9 时回读校验会返回 code=1「PLC 转发失败」。
5. 解锁失败保持锁；失败命令不置 9001（非 MCS 悬空命令），只记流水/WARN/审计。

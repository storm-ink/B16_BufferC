1 Introduction

     1.1 Objectives

            This document specifies the Selete requirement for stocker online.

     1.2 Back Ground

                With 300mm semiconductor Fab line of the future, the fully automatic transport of the carrier in a line is
             demanded as a result of the request about the human engineering and the safety accompanied by the expansion
             of a wafer size, and the increase of the weight of 300mm wafer carrier . For this reason, AMHS equipment is
             required to be integrated organically and cost-effectively with a host system.

              In order to attain this purpose, each AMHS equipment must use the common physical and logical interfaces so
           that AMHS equipment can be interoperable. In order to realize the logical interoperability, I300I and J300
           proposed AMHS system configuration and AMHS integration system as shown in Figure 1 below at "6.2 AMHS
           framework" on CIM Global Joint Guidance. They also specified user requirement of AMHS integration system
           on "AMHS Framework User System requirement Document ".

        Production Equipment Control                   Host System (Supervisor) MES Functions

                                           Standard Communication Protocols,
                                           Messages, State Models, and Functions
                                           must be defined.

       The above-mentioned AMHS framework specifies that the stocker should use Stocker SEM (SEMI E88
    Specification for AMHS Storage SEM) as a communication interface with a host system (AMHS integration
    system).

       In order to realize the interoperable stocker, Selete has analyzed the above-mentioned "AMHS Framework User
    System Requirement Document " and "SEMI E88 Specification for AMHS Storage SEM (Stocker SEM)." The
    result of analysis reveals the following.
     1) In order to realize interoperability of a communication interface, additional specification is needed for

          Stocker SEM
     2) Selete's interpretations must be fixed about the ambiguous points of the description of Stocker SEM itself.
      This specification is intended to realize the online specification of interoperable stocker and to specify the
    additional Selete specification to Stocker SEM and the Selete interpretation.

7.4 Supplements

        7.4.1 CarrierWaitIn Event

        1. As CarrierID to be reported in CarrierWaitIn event, SC should report the following ID: either the ID that
              was acquired by IDReader, or the temporary ID that was generated by SC when abnormalities were
              detected by CarrierIDRead. (CarrierID should not be blank.)

        2. Before CarrierWaitIn event , SC should generate CarrierIDRead event . (The operation of stocker after
              CarrierWaitIn will be as follows. If a carrier ID read is successful, it will follow a host's Transfer command.
              If a carrier ID read fails, it will not wait for a host's Transfer command, but will turn into the original
              operation [for example, an abnormal outgoing process operation] of stocker. For this reason, a host sees
              CarrierIDRead result and judges whether or not Transfer command is issued.

     7.4.2 ZoneCapacityChange Event

1. A host does not positively use the Zone function of Stocker SEM. For this reason, a user should establish only
      one Zone by a stocker, and let the region be the entire rack. Moreover, Zone should not be set to a port.

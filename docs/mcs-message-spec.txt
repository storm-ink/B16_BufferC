Inventory STATE MODEL 3.1. SC State Model RequirementThe state models to be included in the Inventory are described in both SEM and GEM. The following is a list of those state models: 1) Communication State Model (refer to GEM3.2) 2) HSMS-SS state model. (Refer to section 5 of SEMI E37.1 HSMS-SS). 3.1.1. SC State ModelThe purpose of the SC state model is to provide information to the host regarding the overall status of the STBC system.3.1.1.1. INITInitialization of SC components is occurring. This is a non-operational state. No commands from the host will be processed or queued. The system will not move out of this state if there are carriers moving. These carriers must be manually or automatically recovered before moving on to the next state. 3.1.1.2. PAUSINGA system PAUSE command has been received and is being processed. All carriers that are currently moving will continue until complete. Carriers that are currently moving may continue to move but they must not begin another movement. The SC should report the PAUSING state to the operator to prevent accidental loading or unloading. All status requests will be processed. The RESUME command will also be processed. 3.1.1.3. PAUSEDNo carriers are in the process of moving on any of the SC units. All status requests will be processed. The RESUME command will also be processed.3.1.1.4. AUTOSystem is in the normal operational state. Commands are actively processed. 3.1.1.5. NO ALARMThere are no alarms present in the system. 3.1.1.6. ALARMThere are one or more alarms present in the system.3.1.2. Carrier State Model Requirement3.3.1. Carrier State Model The purpose of the Inventory carrier state model is to provide information to the host regarding carrier tracking (the Host will not control carriers) while the carrier is in the domain of the Inventory. The carrier is in the domain of the Inventory when it is in storage or transport internal to the Inventory or on a Inventory interface port (manual, interbay, or intrabay). The equipment shall track each carrier in compliance with the Inventory Carrier State Model. 3.3.1.1. INSTALLEDCarrier in Inventory database. 3.3.1.2. WAIT IN (INSTALLED sub-state)Carrier at an internal input location in the Inventory ready to be moved to a storage or output location 3.3.1.3. WAIT OUT (INSTALLED sub-state)Carrier is at an Output, Buffer, or Loading Port. 3.3.1.4. TRANSFERRING (INSTALLED sub-state)Carrier moving between locations in the Inventory 3.3.1.5. STORED (INSTALLED sub-state)Carrier is sitting at a storage location. 3.3.1.6. COMPLETED (STORED sub-state)The carrier is stored at a shelf location as a result of completing a transfer for which this shelf represents the destination of the transfer command 3.3.1.7. ALTERNATE (STORED sub-state)The carrier is temporarily stored at a shelf location. The transfer command completion is pending until the destination becomes available. 3.3.

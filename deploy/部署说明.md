# BufferC Linux 部署说明（开发文档 §6）

## 目标环境
**CentOS Linux 7.8（glibc 2.17）**，systemd 服务，无人值守 7×24。

> **为什么是 .NET 6**：现场服务器为 CentOS 7.8，glibc 2.17。.NET 7/8 最低要求 glibc 2.23、.NET 9/10 要求更高（dotnet/runtime#83428、#121778），**只有 .NET 6 自包含能在 CentOS 7 上运行**（官方支持过 RHEL7/CentOS7）。工程已从 net10.0 降级到 net6.0（包版本同步降：Microsoft.Data.Sqlite 6.0.36、SQLitePCLRaw.bundle_e_sqlite3 **2.1.4**——**2.1.5 起原生 e_sqlite3 基线抬到 GLIBC_2.28，objdump -T 实测；2.1.4 及以前 ≤2.14，且满足 6.0.36 的最低 2.1.2 约束**；Microsoft.NET.Test.Sdk 17.8.0）。
> 产物已全量符号验证：所有二进制 glibc 依赖 ≤ 2.17（最高 GLIBC_2.16）。
> **ICU**：.NET 6.0.36 runtime 包不含 ICU 本体，CentOS 7 系统库又装不上（yum 已死）——已启用 **InvariantGlobalization**（Host csproj 固定），代码无文化敏感操作（纯数字/hex/显式时间格式），零副作用。**本机可用 CentOS7 WSL 复验**（`wsl -d CentOS7`，rootfs 来自 quay.io centos:7，C:\WSL\CentOS7）。
> 上线前在服务器上先验一次：`ldd --version` 应显示 2.17；把 tgz 解包直接跑 `./BufferC.Host config.json`，若报 `GLIBC_2.2x not found` 说明拷错产物/装错运行时。

## 1. 发布 Linux 产物（开发机 Windows 上执行）

**推荐一键脚本**（发布 → 覆盖现场模板 config → 打 tgz 全自动）：

```
bash deploy/制作现场linux包.sh
```

> 脚本会强制覆盖 `publish/linux-x64/config.json` 为**现场模板**：`agvc.baseUrl` 置空、15 台 PLC 占位 192.168.1.10~24、webPort 7001、logLevel info——**杜绝「发布后忘改 baseUrl 把联调地址带到现场」**（08-14/08-17 各踩一次，人工规程靠不住）。
> 产物为仓库根 `bufferc-linux-x64.tgz`。

手动等效步骤（不推荐，容易漏改 baseUrl）：

```
dotnet publish src/BufferC.Host -r linux-x64 --self-contained -c Release -o publish/linux-x64
tar czf bufferc-linux-x64.tgz -C publish/linux-x64 --exclude='*.pdb' .
```

> - `--self-contained`：产物自带 .NET 运行时，目标机无需安装 .NET。
> - **发布后检查 `publish/linux-x64/config.json` 是否存在**（csproj 已有复制规则，但曾因发布时文件缺失而漏掉——缺它程序直接退出码 2）。

## 2. 打包传输

```
scp bufferc-linux-x64.tgz 用户@服务器IP:/tmp/
scp deploy/bufferc.service 用户@服务器IP:/tmp/
```

> 本机到服务器无直连 SSH 时，改用 U 盘/内网共享拷 tgz，服务器端命令不变。

## 3. 部署

```bash
sudo mkdir -p /opt/bufferc
sudo tar xzf /tmp/bufferc-linux-x64.tgz -C /opt/bufferc
sudo cp /tmp/bufferc.service /etc/systemd/system/
sudo nano /opt/bufferc/config.json      # 填 15 台 PLC IP / unitId / byteOrder
```

> `config.json` 模板已含 15 台 PLC（index 1~15，IP 占位 192.168.1.10~24）。
> **现场核对项**：IP、unitId（1/255）、byteOrder（high/low）、S1F4 结构（config 里 `svidCarrierFormat`）。

## 4. 防火墙（firewalld，CentOS 7 默认）

```bash
sudo firewall-cmd --permanent --add-port=5000/tcp   # HSMS，MCS 连接
sudo firewall-cmd --permanent --add-port=7001/tcp   # Web 监控界面（config webPort）
sudo firewall-cmd --reload
```

## 5. 启动

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bufferc
sudo systemctl status bufferc            # 查看状态
journalctl -u bufferc -f                 # 实时日志
```

## 6. 验证

```bash
curl -s localhost:8080/api/status        # 应有 15 台 PLC 记录（占位 IP 显示离线属预期）
curl -s http://服务器IP:8080/            # Web 界面可访问
```

## 7. 常用运维

| 操作 | 命令 |
|---|---|
| 重启服务 | `sudo systemctl restart bufferc` |
| 停服务 | `sudo systemctl stop bufferc` |
| 看最近日志 | `journalctl -u bufferc -n 200` |
| 数据文件 | `/opt/bufferc/bufferc.db`（库存台账 SQLite） |
| 日志文件 | `/opt/bufferc/bufferc-YYYYMMDD.log` + `/opt/bufferc/bufferc.audit-YYYYMMDD.log`（config.json 配置；按天滚动保留 7 天，启动/跨天自动清理；审计日志含 SECS 收发摘要与命令全生命周期，留档交它） |

## 8. 纯 tgz 手工部署（联调用，不用 systemd）

适合联调期临时跑；**无自动重启/开机自启**，长期运行建议用 §3~§5 的 systemd 方式。

```bash
# 1. 拷贝（无 SSH 就用 U 盘/内网共享）
scp bufferc-linux-x64.tgz root@服务器IP:/tmp/

# 2. 解包
sudo mkdir -p /opt/bufferc
sudo tar xzf /tmp/bufferc-linux-x64.tgz -C /opt/bufferc
sudo chmod +x /opt/bufferc/BufferC.Host      # 必须！tgz 不带执行位（WSL 实测 exit 126）

# 3. 改配置（tgz 里是模板：15 台占位 IP 192.168.1.10~24）
sudo nano /opt/bufferc/config.json

# 4. 防火墙（已放过 5000/8080 则跳过）
sudo firewall-cmd --permanent --add-port=5000/tcp --add-port=8080/tcp && sudo firewall-cmd --reload

# 5. 启动（二选一）
cd /opt/bufferc && ./BufferC.Host config.json                        # 前台：看控制台，Ctrl+C 停
cd /opt/bufferc && nohup ./BufferC.Host config.json > nohup.log 2>&1 &   # 后台：断开 SSH 不受影响

# 6. 验证
curl -s localhost:8080/api/status

# 7. 停止
pgrep -f BufferC.Host          # 找 PID
kill <PID>                     # 优雅停止；前台跑的直接 Ctrl+C
```

> 版本更新时 `tar xzf` 会**覆盖同名 config.json / bufferc.db**——更新前先备份这两个文件，解包后恢复（WSL 预演就是这么做的）。

## 9. 版本更新

```bash
sudo systemctl stop bufferc
sudo tar xzf bufferc-linux-x64.tgz -C /opt/bufferc   # 注意保留 config.json / bufferc.db（tar 会覆盖同名文件，不删除多余文件）
sudo systemctl start bufferc
```
